# 000 怎么启动当前 pipeline

这份文档只保留当前最短可用路径。

## 1. 先说明两个常见疑问

### `NO_PROXY` / `no_proxy` 必须吗

现在不是必须。

本地 OCR / GroundedSAM2 / Depth / CountGD 的 HTTP client 已经改成不继承环境代理，所以即使你 shell 里有 `http_proxy`，访问 `127.0.0.1` 的本地服务也不会再被错误转发。

也就是说，下面这两行现在是可选项，不是硬要求：

```bash
export NO_PROXY=127.0.0.1,localhost
export no_proxy=127.0.0.1,localhost
```

保留也没问题，只是不再是必须条件。

### `--ocr-base-url` / `--grounded-sam2-base-url` / `--depth-base-url` / `--countgd-base-url` 必须吗

也不是必须。

`run_dataset_pipeline.py` 现在默认就是：

- OCR: `http://127.0.0.1:8080`
- GroundedSAM2: `http://127.0.0.1:8081`
- Depth: `http://127.0.0.1:8082`
- CountGD: `http://127.0.0.1:8083`

见 [run_dataset_pipeline.py](/data/home/suchenghao/ToolVision/offline_sft_pipeline/scripts/run_dataset_pipeline.py#L93)。

所以：

- 如果你就是按默认端口启动四个服务，URL 参数可以全省略
- 只有你改了端口，才需要显式传这些 URL

## 2. 启动四个本地服务

进入 CodeVision：

```bash
cd /data/home/suchenghao/ToolVision/CodeVision
```

直接启动四个服务：

```bash
bash scripts/launch_external_services.sh start all
```

这套默认端口是：

- `8080`: PaddleOCR
- `8081`: GroundedSAM2
- `8082`: Depth
- `8083`: CountGD

如果你改端口，就在启动前改环境变量，比如：

```bash
OCR_PORT=18080 GROUNDEDSAM2_PORT=18081 DEPTH_PORT=18082 COUNTGD_PORT=18083 \
bash scripts/launch_external_services.sh start all
```

## 3. 跑 batch pipeline

进入仓库根目录：

```bash
cd /data/home/suchenghao/ToolVision
```

### 3.1 dry-run 版本

这个版本不调真实 planner / executor 大模型 API，但 runtime 仍然走真实本地服务。

适合先验证：

- JSONL 读取
- orchestrator 主流程
- runtime wrapper
- 本地 OCR / GroundedSAM2 / Depth / CountGD 路径
- store / log / trajectory 落盘

命令：

```bash
export OFFLINE_SFT_API_DRY_RUN=1

conda run -n codevision python offline_sft_pipeline/scripts/run_dataset_pipeline.py \
  --input-jsonl offline_sft_pipeline/example/root_samples.jsonl \
  --output-dir offline_sft_pipeline/outputs/dataset_pipeline_runs \
  --run-id dryrun_real_runtime_batch_1 \
  --max-samples 1
```

如果你服务不是默认端口，再补 URL：

```bash
conda run -n codevision python offline_sft_pipeline/scripts/run_dataset_pipeline.py \
  --input-jsonl offline_sft_pipeline/example/root_samples.jsonl \
  --output-dir offline_sft_pipeline/outputs/dataset_pipeline_runs \
  --run-id dryrun_real_runtime_batch_1 \
  --max-samples 1 \
  --ocr-base-url http://127.0.0.1:18080 \
  --grounded-sam2-base-url http://127.0.0.1:18081 \
  --depth-base-url http://127.0.0.1:18082 \
  --countgd-base-url http://127.0.0.1:18083
```

### 3.2 非 dry-run 真实版本

这个版本会真的调用 planner / executor 的 Qwen API。

至少要先设置：

```bash
export OFFLINE_SFT_QWEN_API_KEY='你的真实 key'
unset OFFLINE_SFT_API_DRY_RUN
```

可选项：

```bash
export OFFLINE_SFT_QWEN_BASE_URL='你的兼容接口'
export OFFLINE_SFT_QWEN_MODEL='你的模型名'
export OFFLINE_SFT_QWEN_TIMEOUT_S='120'
```

默认值见 [api_text_multimodal.py](/data/home/suchenghao/ToolVision/offline_sft_pipeline/pipelines/api_text_multimodal.py#L38)。

然后直接跑：

```bash
conda run -n codevision python offline_sft_pipeline/scripts/run_dataset_pipeline.py \
  --input-jsonl offline_sft_pipeline/example/root_samples.jsonl \
  --output-dir offline_sft_pipeline/outputs/dataset_pipeline_runs \
  --run-id real_runtime_batch_1 \
  --max-samples 1
```

如果你的四个本地服务都在默认端口，这里不需要再传 URL。

### 3.3 当前默认模型

当前代码默认会使用：

- `OFFLINE_SFT_QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`
- `OFFLINE_SFT_QWEN_MODEL=qwen3.6-plus`
- `OFFLINE_SFT_QWEN_TIMEOUT_S=120`

如果某次你想临时覆盖，也还是可以在调用前手动 `export` 同名环境变量。

## 4. 看结果看哪里

输出目录：

```text
offline_sft_pipeline/outputs/dataset_pipeline_runs/<run_id>/
```

重点看：

- `run_summary.json`
- `sample_results.jsonl`
- `logs/<sample_id>.log`
- `store/samples/<sample_id>/trajectories/...`

如果只想先确认 runtime 是否真的被调用，优先看每个 step 下的：

- `runtime_result.json`

## 5. 当前一句话结论

- `NO_PROXY` 现在不是必须
- URL 参数现在不是必须，默认端口下可以省略
- 非 dry-run 要求你先配 `OFFLINE_SFT_QWEN_API_KEY`
