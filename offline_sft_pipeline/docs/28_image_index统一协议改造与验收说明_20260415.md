# 28 image_index 统一协议改造与验收说明 2026-04-15

这份文档记录 2026-04-15 这轮改动的目标、实际落地位置，以及建议的验收方式。

本轮核心目标只有一条：

> 把 offline_sft_pipeline 和 CodeVision 的多轮图像输入协议统一到纯 `image_index`，去掉模型可见层的 `root/current` 语义。

---

## 1. 本轮改动结论

当前已经落地的行为是：

1. offline 模型侧协议不再产 `input_image="root/current"`，改为 `input_image_index`。
2. offline 的 `visible_images` 不再只保留 `root + latest`，改为 append-only 全历史时间线。
3. orchestrator 直接按 `input_image_index` 绑定 runtime 默认输入图。
4. executor prompt / planner prompt 都改成显式说明 image timeline。
5. CodeVision `CodeImageTool` 在每次成功执行后，会把输出图 append 回实例级 `images` 列表。
6. 单轮 code block 内 helper 的 active image 切换逻辑保持不变。
7. source switch 不再靠结构字段 `root/current` 表达，而要求在 CoT 中显式说明“为什么回到更早的 image index”。

## 3. 协议变化

### 3.1 旧协议

planner step:

```json
{
  "step_id": "step_1",
  "step_goal": "Run OCR on the crop.",
  "input_image": "current",
  "capability_plan": [...],
  "executor_instruction": "..."
}
```

这套协议的问题是：

- 模型看到的是 `root/current` 抽象，不是最终运行时真实使用的 index。
- offline 过去只给 `root + latest` 两张可选图，和 CodeVision 在线多轮图像历史不一致。
- CodeVision 原实现里，tool 返回的新图虽然会进入消息历史，但不会回写到 tool 自己的工作 `images` 列表。

### 3.2 新协议

planner step:

```json
{
  "step_id": "step_1",
  "step_goal": "Run OCR on the crop.",
  "input_image_index": 1,
  "capability_plan": [...],
  "executor_instruction": "..."
}
```

新协议下：

- `visible_images[0..n-1]` 就是 planner / executor / runtime 共享的同一条局部时间线。
- `input_image_index` 是 step 默认输入图。
- code 内如果想回到别的历史图，仍然通过 helper 的 `image_index=` 显式切换。
- 如果是“从最新图回到更早图”的 source switch，需要在 CoT 里写出原因。

## 4. 运行时语义

### 4.1 offline

offline 当前语义已经是：

- root 图先进入 `visible_images`
- 每个已执行 step 的 primary output 依次 append
- orchestrator 用 `input_image_index` 直接选默认输入图
- runtime 继续用 `RuntimeStepRequest.image_index`

也就是说，offline 这边的“默认 `image/img` 绑定”本来就存在，本轮真正补的是：

- 谁来产这个 index
- 模型看到的候选图是否也是同一条 append-only 历史

### 4.2 CodeVision

CodeVision 当前这轮改完后，目标语义是：

1. create 阶段初始 root 图进入实例 `images`
2. execute 阶段用 `image_index` 选默认输入图
3. 代码成功返回 `processed_image`
4. `processed_image` append 回实例 `images`
5. 下一轮可以直接对这个新增 index 再处理

单轮 code block 内部仍然保留：

- helper 返回后，active `image/img` 切到 helper 输出

这和跨轮 append-only timeline 不冲突。
