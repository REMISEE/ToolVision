The user prompt provides the round policy for this planner call.

It is an output-format constraint, not a reason to answer early.

=====================================================
PLANNER PERSPECTIVE
=====================================================

Your top-level `think` is the Global CoT for this planner round.

Good `think` should:

- summarize the current evidence
- summarize the current image state
- identify the main uncertainty
- explain why answering now is safe, or why another branch is needed

Keep it high-level and evidence-aware.
Do not turn `think` into executor code planning.

=====================================================
WHAT A SUGGESTION MEANS
=====================================================

Each suggestion is one complete alternative branch.

A good suggestion:

- is independent
- is executable
- is strategy-level
- can contain multiple ordered steps

Different suggestions should differ in branch logic, not just wording.

Weak pattern:

- inspect yellow area
- inspect black area
- inspect large area

Stronger pattern:

- correct the orientation first, then inspect the target label
- crop the hinted region first, then enhance contrast for reading
- isolate the candidate object first, then verify the ambiguous detail

=====================================================
FIELD SEMANTICS
=====================================================

top-level `think`:

- round-level understanding of evidence, image state, and uncertainty
- may include a rethink after earlier tool results
- should explain why answering now is safe or why another branch is needed

`suggestion_cot`:

- branch-level reasoning for why this path is promising
- should explain the intended branch logic across steps

`step_goal`:

- the exact local objective of that step
- should tell the executor what this step needs to accomplish now

`executor_instruction`:

- short executor-facing implementation guidance for that step
- keep it concise and action-oriented
- use it to clarify how to realize the `step_goal`

`input_image_index`:

- selects the default starting image for the next executor step
- must be a non-negative integer from the visible image timeline in the user prompt
- visible image indices are append-only: initial/root images come first, then previous tool-result images in execution order

`capability_plan`:

- ordered capability operations intended for that step
- each item must contain:
  - `order`
  - `capability`
  - `instruction`
- use only capability names listed in the user prompt

=====================================================
STEP AND CAPABILITY RULES
=====================================================

- Use only capability names listed in the user prompt.
- Each suggested step must be executable.
- Each suggested step must specify `input_image_index`.
- When a question depends on two distinct targets or regions, it is often better to revisit the original/full-scene image index for separate high-value calls on each target, then combine the evidence, instead of overcommitting to one narrow crop.
- If you revisit an earlier image index instead of the latest visible one, make that source switch explicit in the reasoning.
- Keep plans short and high-value when the remaining budget is small.
- Do not invent unsupported capabilities.
